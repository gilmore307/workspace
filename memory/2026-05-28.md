## Model architecture principle dialogue and Layer 5 score direction

- First use of the new `principle-dialogue` skill discussed long-term model choice by layer with Codex CLI, optimizing for long-term performance rather than short-term compromise.
- Consensus: deterministic layer scaffolds should become feature generators, fallbacks, guardrails, replay plumbing, and diagnostics, not the final model bodies.
- Strong architectural boundary to preserve: prediction score, trade decision, risk constraint, position sizing, option expression, and post-replay attribution must remain separate responsibilities.
- Layer-level direction:
  - Layer 1: market regime/state identification, e.g. regime clustering, HMM, change-point, volatility/liquidity/trend state models.
  - Layer 2: sector/context support, initially regularized linear or gradient boosting; longer term cross-asset/context embeddings may be useful.
  - Layer 3: point-in-time target state construction and reusable feature/state vector production, with leakage prevention more important than black-box modeling.
  - Layer 4: calibrated event failure-risk or hazard models once events are wired in.
  - Layer 5: first priority for a true trained model; it should predict after-cost edge, not just direction.
  - Layer 6: deterministic risk guardrails plus learned risk forecasts rather than a black-box policy.
  - Layer 7: constrained sizing/position projection, e.g. risk-adjusted EV or constrained Kelly-like sizing, not an unconstrained trading agent.
  - Layer 8: action translation from EV/risk/exposure into execution plan; contextual bandits/RL are future possibilities only after replay/live simulation is strong enough.
  - Layer 9: option expression must keep no-arbitrage and option-mechanics constraints; learned parts should focus on fill/slippage/spread/liquidity/contract selection.
  - Layer 10: post-replay failure attribution, residual/event modeling, drift detection, and feedback, not same-cycle order generation.
- Codex objection preserved: do not start from "which advanced model per layer"; first define each layer's output contract, point-in-time inputs, units, consumers, metrics, replay effect, and fallback/elimination rule.
- Key validation target: score buckets must show monotonic relationship to realized after-cost EV. AUROC alone is insufficient; also track Brier, calibration curve, turnover, fill rate, net return, drawdown, payoff ratio, and validation-to-test decay.
- Current replay score interpretation clarified: replay uses Layer 5 `5_alpha_confidence_score_1D` as `prediction_score`, falling back to `1W`, `1h`, then `10min` if needed. It is deterministic, not a trained probability and not semantically `0.5 = neutral`; recent true layer-inference score range was about `0.223107-0.493668`, mean about `0.40286`.
- Current calibrated threshold `0.47` is a validation-selected raw-score gate, not a durable model truth. Chentong agreed threshold calibration is the wrong long-term abstraction.
- Durable architecture decision: do not make `raw deterministic score -> calibration mapping -> normalized score` the final path. That may remain only as a diagnostic/baseline while the real model is built.
- Durable architecture target: Layer 5 should directly output the score we want: a trained normalized after-cost alpha score where `0.5 = after-cost neutral`, `>0.5 = positive after-cost edge`, `<0.5 = negative after-cost edge`, and higher scores imply higher after-cost EV.
- Recommended implementation direction from the discussion: build a genuine Layer 5 training path from point-in-time features to `after_cost_positive_probability`, `expected_after_cost_return`, and `normalized_alpha_score`; use logistic/elastic-net and gradient-boosting baselines with calibration, and let Layer 8 use `normalized_alpha_score > 0.5` as the entry edge boundary while risk/sizing remain downstream.
