## Runtime task-centric architecture and position lifecycle decisions at 2026-05-21 10:46 EDT

- Chentong clarified a major architecture principle: training/model development can remain model/layer-centric, but live runtime and Replay must be task-centric. Models are tools; live/replay components should invoke whichever frozen model capabilities they need for the trading task rather than mechanically running layers in sequence.
- Accepted runtime component shape:
  - Opportunity Scanner
  - Entry Decision Engine
  - Position Lifecycle Controller
  - Option Re-Expression Review
  - Portfolio Risk Allocator
  - Execution Order Intent Builder
  - Event Risk / Failure Explanation Component
- Position management is a core execution/runtime capability, not a new model. Use existing Layers 6/7/8/9 as the decision base for risk budget, target/current position gap, planned action, trade plan, and option expression. The missing work is execution-side lifecycle control that merges model outputs with current account/position/market state and emits replayable `position_lifecycle_decision` and `execution_order_intent` records.
- Option positions need a dedicated lifecycle path because contract quality changes while held. The system should periodically and event-triggeredly review held contracts for moneyness, delta/gamma/theta/vega, DTE, spread, volume/OI, IV, payoff efficiency, and liquidity decay.
- Accepted option re-expression rule: while holding an option, periodically rescore the current contract and scan same-direction candidate contracts using the current thesis. Roll only when the new contract is significantly better after roll-cost penalty and hard gates. Candidate outputs include `hold_option`, `reduce_option`, `exit_option`, `roll_option_candidate`, and `switch_to_underlying_candidate`.
- Conservative initial policy ideas recorded for later design: `roll_review_interval_minutes = 15`, no roll in first 5-15 minutes, require meaningful score/net-utility improvement above estimated roll cost, block rolls to worse spread/liquidity, cap rolls per position/day, and cap total roll cost per position.
- Replay must mirror live runtime flow. It should evaluate the frozen component graph and frozen model group as a replay of real trading behavior, not as a list of standalone model invocations.
- Layer 10 decision is settled for now: keep Layer 10 as an independent `EventRiskGovernor` model and include it in Replay through the frozen runtime component graph. Its decision-chain outputs may affect replayed entry/hold/add/reduce/exit/flatten-review behavior when point-in-time event evidence is available. Its failure-analysis/event-family feedback packets may inform next-generation Layer 4 training, but must not mutate the already-running candidate/replay.
