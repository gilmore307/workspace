## Contract naming version-suffix concern raised
- Chentong objected that names like `component_completion_receipt_payload_v1` should not carry a `v1` suffix in the semantic/business contract name.
- Accepted direction: semantic names should be unversioned, e.g. `component_completion_receipt_payload`, `component_completion_receipt`, `manager_request`, `run_manifest`, `artifact_ref`, `ready_signal`, `current_system_status_summary`, and `historical_task_progress_summary`.
- Preferred versioning location: metadata/schema layer such as `schema_version: 1` and `schema_ref`, not embedded in the business/registry key name.
- Important caution: this must be a controlled compatibility migration, not a global text replacement. Existing `_v1` names are active contract_type/registry/schema/storage path/SQL/doc references and appear broadly across repos (rough initial count during discussion: manager ~969, storage ~122, dashboard ~49).
- Recommended next implementation slice: migrate active public contracts plus component completion receipt naming first, keep legacy `_v1` aliases/read compatibility, update docs/registry with deprecation wording, then run manager/storage/dashboard tests and registry dry-run before pushing.
