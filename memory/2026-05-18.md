## TE data architecture split proposed by Chentong
- Chentong proposed splitting Trading Economics handling into two parts: (1) historical acquisition/preservation as a one-time bootstrap job already effectively completed, after which models should consume the saved TE data through database/source ingestion and the raw downloaded originals can be deleted once fully digested and reproducible; (2) future/realtime updates owned mainly by the realtime trading system, using logged-out recent calendar access to keep near-future release calendars and same-day actual releases updated in the database.
- Proposed fallback principle: during model training, the ideal state is that all needed TE data is already in the database; if gaps exist, fill them by reviewed TE download/fetch or, for public macro releases, by websearch with provenance.
